**Тема:** Асинхронный JavaScript и REST API

## Описание

Одностраничное приложение на HTML, CSS и обычном JavaScript. Оно загружает пять публикаций с [JSONPlaceholder](https://jsonplaceholder.typicode.com/), отправляет новую запись и показывает результат без перезагрузки страницы.

## Файлы

- `index.html` — структура страницы и форма.
- `style.css` — оформление и адаптивная вёрстка.
- `app.js` — обработчики событий, GET/POST-запросы, проверка полей и вывод данных через DOM.
- `README.md` — инструкция и результаты проверки.

## Запуск на Mac в Visual Studio Code

Серверная часть, база данных, `npm` и установка библиотек не нужны.

1. Распакуйте архив и откройте папку `lab3-post-board` в Visual Studio Code: **File → Open Folder…**.
2. Во вкладке **Extensions** (иконка квадратов слева) найдите и установите расширение **Live Server** от Ritwick Dey.
3. Откройте `index.html`, нажмите правой кнопкой мыши по редактору и выберите **Open with Live Server**. Либо нажмите **Go Live** внизу окна.
4. Откроется браузер со страницей приложения (обычно адрес вида `http://127.0.0.1:5500/index.html`).

**Альтернатива без расширения:** откройте Terminal в папке проекта и выполните `python3 -m http.server 8000`, затем перейдите в браузере на `http://localhost:8000`. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

## Результаты проверки

Локальные автоматические проверки JavaScript с имитацией ответов API пройдены: загрузка 5 записей, вывод через DOM, отказ отправлять пустые поля, POST с обрезкой пробелов, вывод заголовка и ID `101`, обработка HTTP 404 и сетевого сбоя, повтор запроса и восстановление активности кнопок. Синтаксис `app.js` также проверен. После публикации на GitHub Pages следует отдельно повторить GET/POST с настоящим JSONPlaceholder в браузере.

## Как проверить работу вручную

| Проверка | Ожидаемый результат |
| --- | --- |
| Кнопка «Загрузить публикации» | Отображаются пять карточек с заголовками и текстом. |
| Повторная загрузка | Данные обновляются без перезагрузки страницы, карточки не дублируются. |
| Отправка пустых полей или одних пробелов | Появляется сообщение об ошибке; POST-запрос не выполняется. |
| Отправка заполненной формы | Выполняется POST с `{ title, body, userId: 1 }`; появляется сообщение об успехе, заголовок и ID публикации (обычно `101`). |
| Ошибка GET | Временно замените значение `POSTS_URL` в `app.js` на `"https://jsonplaceholder.typicode.com/postz"`. При нажатии на загрузку появится понятная ошибка HTTP 404, а кнопка снова станет активной. После теста верните исходную строку. |
| Недоступная сеть | Показывается ошибка; после её устранения можно повторить запрос. |

Состояние загрузки и отправки показывается во время ожидания ответа. Обе операции используют `fetch`, `async/await`, `response.ok`, `try/catch/finally`. Данные выводятся через `textContent`.

> **Важно:** JSONPlaceholder имитирует создание публикации: POST возвращает успешный ответ, но запись не хранится на сервере постоянно.

## Публикация через GitHub Pages

1. Создайте **публичный** репозиторий GitHub и загрузите в его корень файлы `index.html`, `style.css`, `app.js`, `README.md`.
2. Откройте **Settings → Pages**.
3. В разделе **Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/(root)`, затем нажмите **Save**.
4. Дождитесь появления адреса сайта на этой же странице. Откройте его и проверьте GET/POST.
5. В комментарии LMS приложите две ссылки: на репозиторий и на опубликованный сайт.
